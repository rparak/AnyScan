# Python 3.10-3.12; developed and characterized on 3.10 (macOS on Apple silicon,
# for the MLX describer). Version floors below match the imports actually used across App/,
# src/ and Example/ — loosen only if a wheel is unavailable for your platform.

# ---- UI --------------------------------------------------------------------
# The window. At start App/run.py also imports OpenCV, NumPy, Pillow and PyYAML (the
# configuration layer and the UI's image conversion), so the application does not open
# without them; pypylon is imported only when the camera connects, and torch, ultralytics
# and mlx only when a configuration's models load.
PyQt5>=5.15

# ---- capture + segmentation (BaslerCamera and the vision pipeline) ---------
opencv-python>=4.10
# numpy floor is 2.2, not 1.26: ultralytics' default dependency resolution otherwise
# drags numpy down to 1.x (and opencv-python with it), which the rest of the
# environment (torch, mlx-vlm) was reconciled against at 2.x. Install
# ultralytics WITH this pin held — `pip install -r requirements.txt` does that.
numpy>=2.2
Pillow>=10.0
# The configuration and calibration are read from (and the calibration written back to)
# Configuration/*.yaml by Configuration.Core.
PyYAML>=6.0
pypylon>=3.0          # only needed for the live camera; --frame runs without it

# ---- the local Gemma 4 describer (models/gemma-4-e4b-it-4bit) --------------
# An MLX conversion, run on Apple's Metal GPU through MLX — not PyTorch/MPS. Measured on
# macOS on Apple silicon, the machine that drives the camera. Linux is installable but
# unmeasured: there mlx has no compute backend of its own and needs an extra chosen for the
# machine, which lives in a one-line file per backend — requirements/linux-cuda12.txt,
# linux-cuda13.txt or linux-cpu.txt — selected by install.sh from the NVIDIA driver it finds.
# The version is pinned here only; the backend files name the extra without a version, and
# pip combines the two. Installing this file alone on Linux gives mlx without a backend.
# Windows is not a target. Elsewhere the describer reports that MLX is missing
# (README > Platform).
# Pinned EXACTLY, not floored: mlx-vlm's model implementations change between releases
# (gemma4 arrived recently) and an unpinned upgrade could change the descriptions.
# mlx pins its own mlx-metal (macOS) or mlx-cuda-12 / mlx-cuda-13 / mlx-cpu (Linux extras).
mlx==0.32.2 ; (sys_platform == "darwin" and platform_machine == "arm64") or sys_platform == "linux"
mlx-vlm==0.7.2 ; (sys_platform == "darwin" and platform_machine == "arm64") or sys_platform == "linux"
# The `hf` command the README's setup uses to download the Gemma weights. It arrives
# transitively (mlx-vlm -> transformers), but setup depends on it directly, so it is declared.
# Verified with 1.30; `huggingface-cli`, which older instructions used, no longer works there.
huggingface_hub>=1.30

# ---- FastSAM instance segmentation (stage 2 of the vision pipeline) --------
# The bboxes= box-prompt keyword arrived in 8.2; the default everything-mode needs
# nothing special. Pulls matplotlib transitively, so the Segmenter module imports
# ultralytics lazily to keep the Qt-free domain import clean. torch is declared
# because the Segmenter imports it directly (device selection), not only through
# ultralytics. On Linux, install.sh installs torch + torchvision from the PyTorch index for
# the detected backend (cu126 / cu130 / cpu) BEFORE this file, so this line is then already
# satisfied: a CUDA build cannot be chosen by an environment marker, and PyPI's default
# Linux torch is the CUDA 13 build.
torch>=2.3
ultralytics>=8.2

# ---- tests -----------------------------------------------------------------
# The unit suite under test/ and the Example/Vision characterization harness.
# Both run without camera hardware and without the model weights; tests
# that genuinely need the weights are marked `slow` and skipped by default.
pytest>=7.0
